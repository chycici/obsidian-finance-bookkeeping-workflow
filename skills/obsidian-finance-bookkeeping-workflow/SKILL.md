# Obsidian 财务记账工作流

## 一、速查牌（核心5条）

1. 一笔费用一条笔记，原始凭证必须保留
2. 出差费用只放任务页，月度页只做引用
3. 待确认 = 关键字段未定；无发票/支付方式缺失/汇率不算待确认
4. 所有金额展示千分位；导出待确认不并入无发票
5. **任何录入/修改完成后，必须过收口清单（见 DESIGN.md §七）**

## 二、场景入口

| 场景 | 执行方式 |
|------|---------|
| 单笔 PDF 入账 | 见本文 §三 |
| 批量 Excel 导入 | 见本文 §四 |
| 按抬头导出 Excel | 见本文 §五 |
| 移动条目抬头分组 | 见本文 §六 |
| 批量口径规则变更 | 见本文 §七 |

**所有业务规则权威定义见 DESIGN.md §三。**

## 三、单笔 PDF 入账

### 步骤

1. **提取 PDF 内容**：优先 `pdftotext`，备用 OCR
2. **展示识别结果**：向用户列出日期、供应商、金额（原币）、支付方式、抬头
3. **用代码块展示确认模板**（用户直接复制回传）：
   ```
   记到 YYYY-MM，类别XXX，日常/出差，按个人/[公司名]，人民币你帮我查
   ```
4. **查汇率**：外币时查实时汇率，折算 CNY；汇率不算待确认项
5. **调用 create_entry.py**：传入所有字段，脚本负责路径构造、文件复制、条目创建
6. **调用 update_monthly.py**：重算当月统计，更新月度页
7. **调用 validate_links.py**：验证新条目的链接和凭证
8. **过收口清单**

### 判断待确认

用户口令中若有关键字段缺失，在调用 create_entry.py 时将 `status` 设为 `待确认`，`pending_note` 填写具体哪个字段待确认。

## 四、批量 Excel 导入

1. 解析原始 Excel，提取每行数据
2. 字段映射：对照 DESIGN.md §四.1 frontmatter 字段定义
3. 对每行调用 create_entry.py
4. 全部创建完成后调用 update_monthly.py
5. 调用 validate_links.py 做全量检查
6. 生成导入报告（导入说明.md + 导入报告.md）
7. 过收口清单

**覆盖导入时**：保留旧原始文件，删除旧条目文件，重新走完整流程。

## 五、按抬头导出 Excel

1. 运行 validate_links.py，确认当月无严重失效（或已知并标注）
2. 运行 export_excel.py --month YYYY-MM
3. 过 Excel 专项收口清单
4. 向用户提供文件链接

## 六、单笔口径变更（移动条目抬头分组）

同步以下 3 个位置：

1. **条目文件**：修改 `payer` 字段
2. **月度页**：调用 update_monthly.py 全量重算（不手动改数字）
3. **Excel 导出**（如已生成）：重新运行 export_excel.py

注意：`payee` 不变（收款方/开票方），`payer`（付款方/抬头）决定分组。

### 6.1 凭证引用修正陷阱（2026-05-08 经验）

凭证引用有两处**相互独立**，修一处不等于修两处：

| 位置 | 作用 |
|------|------|
| frontmatter `voucher:` | Dataview / 脚本读取 |
| 正文 `## 凭证` 下的 `![[...]]` | Obsidian 内预览显示 |

**修正流程（必要！）：**

1. 确认 voucher 目录下实际存在文件（`ls -la` 验真）
2. 确认文件内容与该条目匹配（OCR / Vision 验证，防止误指向邻行）
3. 同步修改 frontmatter `voucher` 和正文 `## 凭证` 下的嵌入引用

**常见错误模式（已踩过的坑）：**

- `voucher` 字段为空但文件实际存在（seq 18 X Premium）
- `voucher` 字段指向另一条目（seq 18）的凭证图（seq 19 餐饮服务导入时写错）
- 正文 `## 凭证` 写"待补充"或"无"，但 frontmatter 已更正——两处必须同时改

### 6.2 Payer 修正的完整同步链（2026-05-08 经验）

当 `payer` 从空/错误修正为公司抬头时，必须同步以下全部位置（缺一不可）：

| 序号 | 位置 | 具体操作 |
|:----:|------|---------|
| 1 | 条目文件 frontmatter | 改 `payer:` 字段 |
| 2 | 月度页 - 源分组 | 从原组（如"个人"）移除该行和统计 |
| 3 | 月度页 - 目标分组 | 在新组（如"海南云创..."）插入该行和统计 |
| 4 | 月度页 - 汇总行 | 更新总条目数/总金额 |
| 5 | 月度页 - 待确认备注 | 如影响待确认计数需同步更新 |
| 6 | Excel 汇总总表 | 移动行 + 更新小计/合计公式 |
| 7 | Excel 按抬头汇总 | 更新金额和条目数 |
| 8 | 月度页备注 | 加更记录（如 "XX条目抬头更正"） |

**Excel 修改的实操经验**：用 openpyxl 的 `insert_rows()` + `delete_rows()` 做行级操作容易残留混乱数据（公式与数据错行）。**推荐策略：直接重建整个 Sheet 比修补更可靠。**

### 6.3 从 Excel 导入后校验清单

导入后逐一检查以下易错项（2026-05-08 经验）：

- [ ] 每一条目的 `voucher` 字段指向正确的、存在的文件（`ls -la` 验真）
- [ ] 每一条目的 `payer` 字段非空（否则会误落入"个人"分组）
- [ ] 正文 `## 凭证` 下的图片引用与 frontmatter `voucher` 一致
- [ ] 出差条目的 voucher 图没有指向日常条目（反之亦然）
- [ ] 用 OCR/Vision 验证图片内容与摘要描述的匹配性

## 七、批量口径规则变更

1. 更新 DESIGN.md §三 中的权威口径（先改规则文档）
2. 批量修改相关条目 frontmatter
3. 调用 update_monthly.py 重算全部受影响月份
4. 重新生成 Excel 导出
5. 过收口清单

## 八、用户沟通规范

- 记账口径确认模板**必须用代码块**展示，方便用户直接复制
- OCR 无法确认的字段**直接问用户**，不从模糊结果猜测
- 汇率由助手补查，不需要用户提供
- 确认完成后立即执行，不二次确认
