# Obsidian 财务记账工作流 — 完整设计方案

> 本文档描述整套系统的架构、业务规则、数据模型、脚本接口与 SKILL.md 内容，供开发者直接落地代码。

---

## 一、项目背景与目标

### 1.1 背景

用户在 Obsidian（vault 名：`<your-vault>`）中维护个人和公司财务记账系统，由 AI 助手辅助录入、汇总、导出。现有方案完全依赖 SKILL.md 提示词驱动，导致三类高频问题：

1. **统计漏更新**：录入条目后，月度页汇总数字未同步
2. **格式错位**：Markdown 表格列数不对齐、金额未千分位、链接别名与表格分隔符冲突
3. **凭证路径错误**：条目的 `voucher` 字段路径凭摘要推测，指向不存在的文件

### 1.2 目标

- 消除上述三类问题（从"靠提醒"变为"靠约束"）
- 新增按抬头分组的 Excel 导出能力，含公式、千分位、美化、原始凭证超链接
- 保持 AI 助手作为用户沟通和业务判断的入口，脚本层承担所有确定性执行

---

## 二、整体架构

### 2.1 架构决策

采用**混合架构**：

```
用户输入
   │
   ▼
SKILL.md（判断层）
   判断意图、确认口径、提取字段、调用脚本
   │
   ▼
Python 脚本层（执行层）
   确定性地创建文件、更新统计、验证路径、生成 Excel
   │
   ▼
Obsidian Vault 文件系统
```

**SKILL.md 只负责：**
- 理解用户意图
- 向用户确认记账口径（月份、类别、抬头、汇率）
- 从 PDF/描述中提取字段
- 判断是否"待确认"
- 调用对应脚本，并向用户汇报结果

**脚本层负责：**
- 按公式构造所有文件路径
- 创建完整条目笔记（frontmatter + 正文）
- 重算月度页统计并精确更新
- 验证所有 `[[...]]` 链接和凭证路径
- 生成带公式、美化、超链接的 xlsx

### 2.2 文件组织

```
财务记账工作流/
├── SKILL.md                  ← AI 助手行为指令（精简版）
├── DESIGN.md                 ← 本设计文档
└── scripts/
    ├── create_entry.py       ← 创建条目笔记
    ├── update_monthly.py     ← 更新月度页统计
    ├── validate_links.py     ← 验证链接与凭证路径
    └── export_excel.py       ← 按抬头导出 Excel
```

脚本运行环境：Python 3.10+，依赖 `python-frontmatter`、`openpyxl`、`pathlib`

## 三、业务规则（权威口径）

> 本节是所有业务判断的唯一来源。脚本和 SKILL.md 均以本节为准，不在其他地方重复定义。

### 3.1 待确认（status: 待确认）

**算作待确认的情形：**
- 发票/收据状态不明（不知道有没有）
- 抬头/付款方（payer）不明确
- 报销类型（reimbursement_type）未定
- 拆分口径不明（一笔费用应拆成几条）
- 用途/类别（category）不明
- 凭证缺失（应有但找不到）
- 金额本身存在歧义

**不算待确认的情形：**
- 本来就无发票（记 `invoice_status: 无发票`，`status: 已记录`）
- 支付方式（pay_method）缺失
- 汇率需补查（由系统/助手补查，不影响 status）

**待确认的展示要求：**
- 条目正文开头加红色引用块：`> ⚠️ 待确认：[具体说明哪个字段待确认]`
- 月度页在"待确认条目"区域单列可点击链接 `[[条目路径]]`
- 月度页统计中，待确认条目**参与**总金额/分类金额求和，不剔除

**待确认的导出要求：**
- Excel 中待确认行整行标红
- 发票状态统计中，`待确认` 保持独立列，**不合并**到 `无发票`

### 3.2 发票状态枚举（invoice_status）

| 值 | 含义 | 统计归属 |
|----|------|---------|
| `有发票` | 有正式增值税发票 | 有发票金额 |
| `有收据` | 有收据/回执但非正式发票 | 有收据金额 |
| `无发票` | 明确无发票（正常情况，不需要） | 无发票金额 |
| `待确认` | 不确定是否有或能否获取 | 待确认金额（独立统计） |

四类互斥，覆盖全部情形。统计时：有发票金额 + 有收据金额 + 无发票金额 + 待确认金额 = 总金额。

### 3.3 抬头分组规则（payer 字段）

**单独成组（精确匹配）：**
- `北京盛通佳达科技有限公司`
- `成都汇智迅析科技有限公司`
- `海南云创软通科技有限公司`

**其余全部归入：**
- `个人`

`payer` 字段决定分组归属。`payee`（收款方/开票方）不影响分组，不要混淆。

发票上："购买方" = `payer`；"销售方" = `payee`。

### 3.4 出差费用原则

- 出差条目详细建账 → **任务页**（`财务记账/出差任务/YYYY-MM-任务名.md`）
- 月度页只写一句引用："出差费用详见 [[财务记账/出差任务/YYYY-MM-任务名]]"
- 月度页**不显示**出差金额总计，**不出现**"出差任务"统计区块
- 目的：防止月度页与任务页重复计算导致重复报销

## 四、数据模型

### 4.1 条目笔记完整模板

每条费用对应一个 Markdown 文件，完整结构如下：

```markdown
---
title: YYYY-MM-DD 摘要描述
date: YYYY-MM-DD
type: expense
category: 域名|云计算|餐饮|交通|住宿|办公|其他
reimbursement_type: 日常|出差
amount: 267.25
currency: CNY|USD|SGD|EUR|HKD|JPY
amount_cny: 1437.81
invoice_status: 有发票|有收据|无发票|待确认
pay_method: MasterCard ****8783|支付宝|微信|银行转账|现金|在线支付
payer: 北京盛通佳达科技有限公司|成都汇智迅析科技有限公司|海南云创软通科技有限公司|个人
payee: 收款方名称
location: 北京|在线|上海|...
project:
trip_name:
status: 已记录|待确认
voucher: 财务记账/原始凭证/YYYY-MM/摘要关键词/原始文件名.pdf
---

## 说明

费用用途说明、背景描述。

## 凭证

![[财务记账/原始凭证/YYYY-MM/摘要关键词/原始文件名.pdf]]

> ⚠️ 此路径必须与 frontmatter `voucher` 字段完全一致。

## 待确认事项

（仅当 status=待确认 时填写，说明具体哪个字段待确认及原因。status=已记录 时删除此节。）
```

**重要约束：**
- `voucher` frontmatter 字段 与 `## 凭证` 段落的路径**必须完全一致**，两处独立存储，必须同时写/同时改
- `amount_cny` 字段存储数值（不加千分位），用于脚本计算
- 展示时所有金额加千分位，但 frontmatter 存原始数值

### 4.2 月度页数据结构

月度页（`财务记账/按月/YYYY-MM.md`）固定区块：

```markdown
## 汇总

| 指标 | 数值 |
|------|------|
| 条目总数 | N |
| 总金额（CNY） | X,XXX.XX |
| 有发票金额 | X,XXX.XX |
| 有收据金额 | X,XXX.XX |
| 无发票金额 | X,XXX.XX |
| 待确认金额 | X,XXX.XX |

## 待确认条目

- [[财务记账/条目/YYYY-MM/YYYY-MM-DD-NN-摘要]]
- ...

## 明细

### 北京盛通佳达科技有限公司

| 序号 | 日期 | 摘要 | 类别 | 金额（CNY） | 发票状态 | 凭证 |
|------|------|------|------|------------|---------|------|
| 01 | 2026-05-03 | ... | ... | 1,234.56 | 有发票 | [[财务记账/条目/YYYY-MM/文件名]] |

**小计：X,XXX.XX**

### 成都汇智迅析科技有限公司
...

### 海南云创软通科技有限公司
...

### 个人
...

## 出差费用

出差费用详见 [[财务记账/出差任务/YYYY-MM-任务名]]
（如当月无出差，删除此节）
```

**约束：**
- 明细表中链接列使用 `[[完整路径]]`，**禁止** `[[路径|别名]]` 写法（`|` 与表格分隔符冲突）
- 如需"查看"文字，单独加一列，不写别名
- 金额列全部千分位展示

```
<your-vault>/
└── 财务记账/

    ├── 收集箱.md
    ├── 待补充.md
    ├── 已报销归档.md
    ├── 按月汇总.md
    ├── 按任务汇总.md
    ├── 条目/
    │   └── YYYY-MM/

    ├── 按月/
    │   └── YYYY-MM.md
    ├── 出差任务/
    │   └── YYYY-MM-任务名.md
    ├── 原始凭证/
    │   └── YYYY-MM/
    │       └── 摘要关键词/
    │           └── 原始文件名.pdf
    ├── 导入/
    │   └── YYYY-MM-批次描述/

### 5.2 文件命名公式

| 文件类型 | 命名公式 | 示例 |
|---------|---------|------|
| 条目文件 | `YYYY-MM-DD-NN-摘要.md`（NN=两位序号） | `2026-05-03-01-GoDaddy域名.md` |
| 月度页 | `YYYY-MM.md` | `2026-05.md` |
| 任务页 | `YYYY-MM-任务名.md` | `2026-04-北京出差.md` |
| 导入批次目录 | `YYYY-MM-批次描述/` | `2026-04-历史导入/` |
| Excel 导出 | `YYYY-MM-费用导出.xlsx` | `2026-05-费用导出.xlsx` |

**序号 NN 计算规则：** 读取 `财务记账/条目/YYYY-MM/` 目录下所有文件，提取文件名中第三段数字，取最大值 +1；目录为空则从 `01` 开始。

### 5.3 凭证路径公式（权威）

```
凭证文件夹 = 财务记账/原始凭证/{YYYY-MM}/{摘要关键词}/
凭证文件名 = 保留原始文件名，不改名，不截断
voucher 字段值 = {凭证文件夹}{凭证文件名}
## 凭证 段落 = ![[{与 voucher 字段完全相同的路径}]]
```

**摘要关键词**：从文件摘要或 payee 中提取 2-4 个有辨识度的词，去除特殊字符，用下划线连接。示例：`GoDaddy_AI域名`、`阿里云_ECS`。

**路径验证**：脚本写入 `voucher` 字段前，必须调用 `os.path.exists(vault_root / voucher_path)` 确认文件存在。不存在则抛出异常，不允许写入不存在的路径。

### 6.1 create_entry.py

**功能：** 创建一条完整的条目笔记（frontmatter + 正文 + ## 凭证 + ## 待确认事项），并将凭证文件复制到正确位置。

**输入参数（JSON 或 CLI）：**

```json
{
  "vault": "/path/to/<your-vault>",
  "date": "2026-05-03",
  "title_summary": "GoDaddy AI域名注册",
  "category": "域名",
  "reimbursement_type": "日常",
  "amount": 267.25,
  "currency": "SGD",
  "amount_cny": 1437.81,
  "invoice_status": "有收据",
  "pay_method": "MasterCard ****8783",
  "payer": "个人",
  "payee": "GoDaddy.com, LLC",
  "location": "在线",
  "project": "",
  "trip_name": "",
  "status": "已记录",
  "description": "注册 arthemissystech.ai 域名，有效期一年",
  "pending_note": "",
  "source_voucher_path": "/tmp/GoDaddy_Receipt_4071051488.pdf"
}
```

**核心逻辑：**

1. 计算序号 NN：扫描 `财务记账/条目/YYYY-MM/` 目录，提取现有文件名中的序号，取最大值 +1
2. 构造凭证目标路径：`财务记账/原始凭证/YYYY-MM/{摘要关键词}/{原始文件名}`
3. 验证 `source_voucher_path` 文件存在；如不存在，抛出 `FileNotFoundError`
4. 复制凭证文件到目标路径（创建中间目录）
5. 验证目标路径文件确实存在（复制成功确认）
6. 构造完整条目文件内容（frontmatter + 正文模板）
7. 写入 `财务记账/条目/YYYY-MM/YYYY-MM-DD-NN-摘要.md`
8. 输出 JSON 结果供调用方使用：

```json
{
  "entry_path": "财务记账/条目/2026-05/2026-05-03-01-GoDaddy域名.md",
  "voucher_path": "财务记账/原始凭证/2026-05/GoDaddy_AI域名/GoDaddy_Receipt_4071051488.pdf",
  "sequence_number": 1,
  "status": "success"
}
```

**错误处理：**
- `source_voucher_path` 不存在 → 报错，不创建条目
- `payer` 不在合法抬头列表 → 自动归入 `个人`，输出 warning
- `invoice_status` 不在枚举值内 → 报错

### 6.2 update_monthly.py

**功能：** 读取指定月份的所有条目文件，重新计算统计数据，更新月度页的汇总区块和明细区块。

**关键设计决策：每次全量重算，不做增量更新。** 避免增量累积误差。

**输入参数：**

```
python update_monthly.py --vault /path/to/vault --month 2026-05
```

**核心逻辑：**

1. 扫描 `财务记账/条目/2026-05/` 下所有 `.md` 文件
2. 用 `python-frontmatter` 解析每个文件的 frontmatter
3. 按 `payer` 字段分组（见§三.3 抬头分组规则）
4. 计算汇总数据：
   - 总条目数、总金额（CNY）
   - 按 `invoice_status` 分类：有发票金额、有收据金额、无发票金额、待确认金额
   - 四类金额之和必须等于总金额（内部校验，不等则报错）
5. 收集 `status=待确认` 的条目路径
6. 按各抬头组构建明细表（按 `date` 升序排列）
7. 读取现有月度页，替换以下区块（其他内容保留不动）：
   - `## 汇总` 区块（整体替换）
   - `## 待确认条目` 区块（整体替换）
   - `## 明细` 区块（整体替换）
8. 写回月度页

**明细表格生成规则：**
- 列顺序：序号、日期、摘要、类别、金额（CNY）、发票状态、凭证
- 金额列：千分位格式字符串（`1,234.56`）
- 凭证列：`[[条目文件完整路径]]`（**禁止**带 `|` 别名）
- 每个抬头组末行加粗小计：`**小计：X,XXX.XX**`
- 表格列宽用 `---` 对齐，确保列数与表头完全一致

**输出：**

```json
{
  "month": "2026-05",
  "total_entries": 15,
  "total_cny": 23450.67,
  "by_invoice_status": {
    "有发票": {"count": 8, "amount": 15000.00},
    "有收据": {"count": 3, "amount": 4500.00},
    "无发票": {"count": 3, "amount": 3000.00},
    "待确认": {"count": 1, "amount": 950.67}
  },
  "pending_entries": ["财务记账/条目/2026-05/2026-05-10-03-xxx.md"],
  "checksum_ok": true,
  "status": "success"
}
```

**错误处理：**
- 某条目 `amount_cny` 字段为空或非数字 → 跳过该条目，输出 warning，继续处理其余条目
- 四类金额之和 ≠ 总金额（浮点误差阈值 0.01）→ 报错，不写入月度页
- 月度页不存在 → 创建新月度页（用模板）

### 6.3 validate_links.py

**功能：** 扫描指定月份（或整个 vault）的所有 Markdown 文件，验证 `[[...]]` 链接和 `voucher` 字段路径的可达性。

**输入参数：**

```
python validate_links.py --vault /path/to/vault --month 2026-05
# 或全量扫描
python validate_links.py --vault /path/to/vault --all
```

**核心逻辑：**

1. 收集目标范围内所有 `.md` 文件
2. 对每个文件：
   a. 解析 frontmatter，提取 `voucher` 字段值
   b. 用正则 `\[\[([^\]|]+)(?:\|[^\]]*)?\]\]` 提取正文所有内部链接
   c. 验证 `voucher` 路径：`os.path.exists(vault_root / voucher_value)`
   d. 验证每条 `[[...]]` 链接：尝试 `vault_root / link_path` 和 `vault_root / link_path + ".md"`
3. 汇总所有失效链接和失效凭证路径

**输出报告格式：**

```json
{
  "scanned_files": 45,
  "broken_links": [
    {
      "source_file": "财务记账/按月/2026-05.md",
      "broken_link": "财务记账/条目/2026-05/2026-05-10-03-xxx",
      "type": "internal_link"
    }
  ],
  "broken_vouchers": [
    {
      "source_file": "财务记账/条目/2026-05/2026-05-03-01-GoDaddy域名.md",
      "voucher_path": "财务记账/原始凭证/2026-05/GoDaddy/xxx.pdf",
      "type": "voucher_not_found"
    }
  ],
  "total_broken": 2,
  "status": "有问题"
}
```

**使用场景：** 在 `export_excel.py` 运行前自动调用；批量导入完成后调用；用户手动触发检查。

### 6.4 export_excel.py

**功能：** 读取指定月份的所有条目，按抬头分组，生成一个包含多 Sheet 的美化 xlsx 文件。

**输入参数：**

```
python export_excel.py --vault /path/to/vault --month 2026-05
```

**输出文件：** `{vault}/财务记账/导出/2026-05/2026-05-费用导出.xlsx`

#### 6.4.1 文件结构

```
2026-05-费用导出.xlsx
├── Sheet: 总览
├── Sheet: 北京盛通佳达科技有限公司
├── Sheet: 成都汇智迅析科技有限公司
├── Sheet: 海南云创软通科技有限公司
└── Sheet: 个人
```

Sheet 顺序固定，即使某抬头当月无数据也保留空 Sheet（仅表头）。

#### 6.4.2 各抬头 Sheet 结构（从上到下）

**行1：标题行**
- 合并单元格 A1:M1
- 内容：`2026年05月 [抬头名] 费用明细`
- 样式：深蓝底色 `#1F3864`，白色加粗，字号 14，居中

**行2：空行（视觉分隔）**

**行3：汇率参考行**（当月有外币条目时显示，否则跳过）
- 格式：`1 SGD = 5.38 CNY`（每种外币一行）
- 样式：浅黄底色 `#FFF2CC`，说明文字颜色
- 此行数据不参与公式计算，仅供查看

**行N：发票状态汇总行**
- 内容：`有发票: 8条 / 15,000.00 | 有收据: 3条 / 4,500.00 | 无发票: 3条 / 3,000.00 | 待确认: 1条 / 950.67`
- 由 COUNTIF/SUMIF 公式动态计算（引用明细行区域）
- 样式：浅蓝底色 `#DEEAF1`，加粗

**行N+1：表头行**（冻结此行）
- 列定义（13列）：

| 列 | 列头 | 数据来源 | 格式 |
|----|------|---------|------|
| A | 序号 | 条目序号 NN | 居中 |
| B | 日期 | frontmatter `date` | `YYYY-MM-DD`，居中 |
| C | 摘要 | frontmatter `title` | 左对齐 |
| D | 类别 | frontmatter `category` | 居中 |
| E | 报销类型 | frontmatter `reimbursement_type` | 居中 |
| F | 原币金额 | frontmatter `amount` | `#,##0.00`，右对齐 |
| G | 币种 | frontmatter `currency` | 居中 |
| H | 汇率 | 当日汇率（CNY/原币） | `0.0000`，右对齐 |
| I | CNY金额 | `=F{n}*H{n}` | `#,##0.00`，右对齐 |
| J | 发票状态 | frontmatter `invoice_status` | 居中 |
| K | 支付方式 | frontmatter `pay_method` | 居中 |
| L | 收款方 | frontmatter `payee` | 左对齐 |
| M | 凭证 | `=HYPERLINK(...)` | 蓝色超链接，居中 |

**注意：** CNY金额列（I列）使用公式 `=F{n}*H{n}`，而非直接填 `amount_cny` 值。`amount_cny` 作为校验用，导出时以公式计算值为准。

**行N+2 起：明细行**
- 按 `date` 升序排列
- 待确认条目（`status=待确认`）：整行底色 `#FFE0E0`（浅红）
- CNY=0 的条目（金额异常）：整行底色 `#FFF2CC`（浅黄警告色）

**最后行：小计行**
- A列：`小计`
- F列：`=SUM(F{数据起始行}:F{数据末行})`（原币，仅当单币种时有意义）
- I列：`=SUM(I{数据起始行}:I{数据末行})`（CNY总计）
- 样式：浅灰底色 `#F2F2F2`，加粗，上边框加粗

#### 6.4.3 总览 Sheet 结构

| 列A | 列B：条目数 | 列C：总金额CNY | 列D：有发票 | 列E：有收据 | 列F：无发票 | 列G：待确认 |
|-----|-----------|--------------|-----------|-----------|-----------|-----------|
| 北京盛通佳达科技有限公司 | 引用对应Sheet | 引用对应Sheet | ... | ... | ... | ... |
| 成都汇智迅析科技有限公司 | ... | ... | ... | ... | ... | ... |
| 海南云创软通科技有限公司 | ... | ... | ... | ... | ... | ... |
| 个人 | ... | ... | ... | ... | ... | ... |
| **合计** | `=SUM(B2:B5)` | `=SUM(C2:C5)` | ... | ... | ... | ... |

跨 Sheet 引用公式示例（C2引用北京盛通Sheet的小计行I列）：
```
='北京盛通佳达科技有限公司'!I{小计行行号}
```

总览 Sheet 发票状态各列同理引用各Sheet的发票状态汇总行对应单元格。

#### 6.4.4 公式规范

| 公式类型 | 写法 |
|---------|------|
| CNY折算 | `=F{n}*H{n}`（F=原币金额，H=汇率） |
| 分组CNY小计 | `=SUM(I{start}:I{end})` |
| 发票状态计数 | `=COUNTIF(J{start}:J{end},"有发票")` |
| 发票状态金额 | `=SUMIF(J{start}:J{end},"有发票",I{start}:I{end})` |
| 跨Sheet引用 | `='Sheet名'!I{row}` |
| 凭证超链接 | `=HYPERLINK("file:///{vault绝对路径}/{voucher相对路径}","查看")` |

**CNY=原币时**（currency=CNY）：H列填 `1`，公式自动处理。

#### 6.4.5 美化规范

| 元素 | 规范 |
|------|------|
| 表头行 | 深蓝 `#1F3864`，白色加粗 14pt，冻结 |
| 汇总统计行 | 浅蓝 `#DEEAF1` |
| 汇率参考行 | 浅黄 `#FFF2CC` |
| 待确认明细行 | 浅红 `#FFE0E0` |
| 金额异常行 | 浅黄 `#FFF2CC` |
| 小计行 | 浅灰 `#F2F2F2`，加粗，上边框加粗 |
| 金额列（F/I） | 右对齐，`#,##0.00` |
| 日期列（B） | 居中，`YYYY-MM-DD` |
| 序号列（A） | 居中 |
| 凭证列（M） | 蓝色 `#0563C1`，下划线，居中，列宽固定 8 |
| 全表边框 | 细实线 `thin`，表头下方 `medium` 加粗线 |
| 列宽 | A:6, B:12, C:30, D:10, E:10, F:12, G:6, H:8, I:14, J:10, K:18, L:20, M:8 |

#### 6.4.6 实现要点

- **始终从头重建 Sheet**，禁止使用 `insert_rows()` / `delete_rows()`（会导致公式偏移）
- 先调用 `validate_links.py` 检查凭证路径，将失效路径记录在 Excel 注释中（不阻断生成，但标注）
- 凭证超链接使用 vault 的**绝对路径**（`os.path.abspath`），确保跨平台可点击
- 按 `date` 升序排列，同日期按序号 NN 排列
- openpyxl 写入完成后，读取小计单元格的计算值做数值校验（需设置 `data_only=False`，用公式字符串校验正确性）

## 七、收口清单（强制出口）

每次执行完任何操作后，助手**必须**按此清单逐项确认，不允许跳过。

### 7.1 通用收口清单（单笔入账 / 修改 / 口径变更后）

```
□ 条目 frontmatter：payer、invoice_status、voucher 字段均已填写，非空
□ 条目正文 ## 凭证：路径与 frontmatter voucher 字段完全一致（两处独立，必须都填）
□ 凭证文件：已通过 os.path.exists 核实文件存在，非凭摘要推测
□ 已调用 update_monthly.py 重算月度页（不允许手动修改月度页统计数字）
□ 月度页明细表：新行已追加，列数与表头列数一致
□ 月度页明细表：无 [[路径|别名]] 写法（只用 [[路径]]）
□ 统计校验：有发票+有收据+无发票+待确认金额之和 = 总金额（误差 < 0.01）
□ 已调用 validate_links.py 验证本次新增/修改的链接和凭证路径
□ log.md：已追加本次操作记录（日期、操作类型、条目路径）
```

### 7.2 Excel 导出专项收口清单

```
□ 已先运行 validate_links.py，确认当月凭证路径无失效（或已知失效已标注）
□ 各 Sheet 小计行 I 列值 = 明细行 I 列之和（数值校验，非肉眼）
□ 总览 Sheet 各抬头数字引用公式正确（跨 Sheet 公式已验证）
□ 待确认行已标红，未出现在发票状态"无发票"统计中
□ 所有金额列格式为 #,##0.00
□ 凭证超链接：所有路径为绝对路径，文件存在
□ 发票状态四类之和 = 本 Sheet 总条目数
```

# Obsidian 财务记账工作流

## 一、速查牌（核心5条）

1. 一笔费用一条笔记，原始凭证必须保留
2. 出差费用只放任务页，月度页只做引用
3. 待确认 = 关键字段未定；无发票/支付方式缺失/汇率不算待确认
4. 所有金额展示千分位；导出待确认不并入无发票
5. **任何录入/修改完成后，必须过收口清单（见 DESIGN.md §七）**

## 二、场景入口

| 场景 | 执行方式 |
|------|---------|
| 单笔 PDF 入账 | 见本文 §三 |
| 批量 Excel 导入 | 见本文 §四 |
| 按抬头导出 Excel | 见本文 §五 |
| 移动条目抬头分组 | 见本文 §六 |
| 批量口径规则变更 | 见本文 §七 |

**所有业务规则权威定义见 DESIGN.md §三。**

## 三、单笔 PDF 入账

### 步骤

1. **提取 PDF 内容**：优先 `pdftotext`，备用 OCR
2. **展示识别结果**：向用户列出日期、供应商、金额（原币）、支付方式、抬头
3. **用代码块展示确认模板**（用户直接复制回传）：
   ```
   记到 YYYY-MM，类别XXX，日常/出差，按个人/[公司名]，人民币你帮我查
   ```
4. **查汇率**：外币时查实时汇率，折算 CNY；汇率不算待确认项
5. **调用 create_entry.py**：传入所有字段，脚本负责路径构造、文件复制、条目创建
6. **调用 update_monthly.py**：重算当月统计，更新月度页
7. **调用 validate_links.py**：验证新条目的链接和凭证
8. **过收口清单**

### 判断待确认

用户口令中若有关键字段缺失，在调用 create_entry.py 时将 `status` 设为 `待确认`，`pending_note` 填写具体哪个字段待确认。

## 四、批量 Excel 导入

1. 解析原始 Excel，提取每行数据
2. 字段映射：对照 DESIGN.md §四.1 frontmatter 字段定义
3. 对每行调用 create_entry.py
4. 全部创建完成后调用 update_monthly.py
5. 调用 validate_links.py 做全量检查
6. 生成导入报告（导入说明.md + 导入报告.md）
7. 过收口清单

**覆盖导入时**：保留旧原始文件，删除旧条目文件，重新走完整流程。

## 五、按抬头导出 Excel

1. 运行 validate_links.py，确认当月无严重失效（或已知并标注）
2. 运行 export_excel.py --month YYYY-MM
3. 过 Excel 专项收口清单
4. 向用户提供文件链接

## 六、单笔口径变更（移动条目抬头分组）

同步以下 3 个位置：

1. **条目文件**：修改 `payer` 字段；如凭证路径有误同步修改 frontmatter `voucher` 和正文 `## 凭证`（两处独立，必须同时改）
2. **月度页**：调用 update_monthly.py 全量重算（不手动改数字）
3. **Excel 导出**（如已生成）：重新运行 export_excel.py

注意：`payee` 不要改，`payer` 决定分组。

## 七、批量口径规则变更

1. 更新 DESIGN.md §三 中的权威口径（先改规则文档）
2. 批量修改相关条目 frontmatter
3. 调用 update_monthly.py 重算全部受影响月份
4. 重新生成 Excel 导出
5. 过收口清单

## 八、用户沟通规范

- 记账口径确认模板**必须用代码块**展示，方便用户直接复制
- OCR 无法确认的字段**直接问用户**，不从模糊结果猜测
- 汇率由助手补查，不需要用户提供
- 确认完成后立即执行，不二次确认
```

## 十、错误处理规范

所有脚本遵循统一的错误输出格式：

```json
{
  "status": "error",
  "error_code": "VOUCHER_NOT_FOUND",
  "message": "凭证文件不存在：财务记账/原始凭证/2026-05/xxx/yyy.pdf",
  "recoverable": false
}
```

| error_code | 含义 | recoverable |
|-----------|------|------------|
| `VOUCHER_NOT_FOUND` | 凭证文件路径不存在 | false（不允许写入） |
| `INVALID_INVOICE_STATUS` | invoice_status 不在枚举值内 | false |
| `CHECKSUM_FAILED` | 分类金额之和 ≠ 总金额 | false（不写月度页） |
| `ENTRY_FILE_EXISTS` | 条目文件已存在（序号冲突） | true（自动递增序号） |
| `MONTHLY_PAGE_NOT_FOUND` | 月度页不存在 | true（自动创建） |
| `BROKEN_LINK_FOUND` | 发现失效链接 | true（生成报告，不阻断） |

`recoverable: false` 的错误：脚本立即退出，不做任何文件写入。  
`recoverable: true` 的错误：记录 warning，继续执行，最终报告中列出。
```
